# Plan: widget data formats (#692)

Each widget describes the format of its data. Eva writes a `DATA_FORMAT.md` in each data folder, adds the widget's prompt line to the Assistant prompt, and checks the data files against the schemas.

## Modules

1. `src/core/widgets/data-formats.ts`: no disk. It reads the fields of a JSON Schema, at every level, and merges the fields of several widgets. A field with two types, two formats or two lists of allowed values is a conflict. No field equivalences.
2. `src/core/widgets/data-format-file.ts`: no disk. It builds the text of `DATA_FORMAT.md` from the merged fields. The first line is "Generated by Eva. Do not edit. Write your notes in the AGENTS.md or the README.md of this folder."
3. `src/core/widgets/data-format-record.ts`: the hash of each `DATA_FORMAT.md` that Eva wrote, in `state/data-formats.json` on the hub. It is apart from `.eva/template.json`, because `align()` deletes a path that is not a template part. It reuses `contentHash`.
4. `src/core/widgets/data-check.ts`: checks one data file against a schema with `ajv`, and gives one sentence for each problem, with the file and the field.
5. `Widgets` (`widgets.ts`):
   - The approval record keeps the manifest's `prompt` (new optional field `prompt`). A record from before has none, so it gets the default line.
   - `approve()` compares the formats of the folder. On a conflict, it throws `widget_format_conflict`. The person then approves with `readOnly: true`: each input with a conflict gets read access and no schema.
   - `syncFormats()`: only the hub. It writes each `DATA_FORMAT.md` from the approved records that match `.eva/widgets.json`, inside `exclusive`. It runs after an approval, a removal and each sync step.
   - `promptLines()`: one line for each widget that is on, with the person's real paths.
   - A `PUT` checks the file against the writer's own schema, and refuses it with the reason.
   - `checkFiles(paths)`: checks the files that a turn changed against each schema whose pattern covers them. It skips a file that a widget wrote, by its hash.
6. `AssistantPreparer`: keeps the widget lines with the projects for the chat. After a turn it asks the vault for the changed files between the two snapshots, and checks them. A problem after a finished turn gives a follow-up message to the agent. A problem after the fix, or after a stopped turn, becomes a note of the turn in the chat.
7. `VaultSync.changedFiles(before, after)`: the paths that changed between two snapshots, or null when a snapshot is missing.
8. `SessionManager`: `TurnOutcome.addNote(text)` adds a note to the turn that ended, and sends a `notice`.
9. Web: the activation shows the prompt line, and on a conflict a warning with "Turn on with read access only".
10. `docs/widgets.md`: the data format file, the merge rules, the checks and the prompt line.

## Gaps and decisions

- **Where the format of a file input lives.** Decision: in the folder of the file, for that one file name. A file at the vault root gets no `DATA_FORMAT.md`.
- **Which schema checks a file after a turn.** Decision: each schema of the folder whose `files` pattern covers the file name. A file that no pattern covers is not data of a widget.
- **A widget that only reads, with a schema.** Decision: it counts in `DATA_FORMAT.md` and in the check.
- **When Eva writes the file again.** Decision: when the text that Eva would write changes, or the file is missing. An edit with no change of format stays until the next change. Eva then rewrites the file and sends one notice.
- **The hub has no record yet**, such as a new hub. Decision: an existing file that does not start with the generated line counts as edited. Other files are rewritten with no notice.
- **Two formats of one field.** Decision: a conflict when both fields give a `type` and the types differ, when both give a `format` that differs, or when both give allowed values (`enum` or `const`) that differ. `integer` and `number` differ.
- **A fix that fails.** Decision: one follow-up message. When the files still fail after it, Eva adds a note to the turn. A stopped or failed turn gets the note at once, with no follow-up.
