# Plan review, 2026-10-14

Seven agents reviewed `plan.md`, `intent.md` and `lessons-from-v1.md` against the design conversation and the v1 vault. Each had one role: fidelity, v1 lessons, security, technical facts, simplicity, migration, and a second person's setup. This file merges their findings and records what happens to each one.

**Disposition.**

- `accept`: the plan changes as described.
- `owner`: the owner must decide. The question is in the conversation of 2026-10-14.
- `reject`: no change, with the reason.

## Final round, 2026-10-14

After the owner approved the plan, three agents reviewed it once more: a decisions ledger, implementability for an autonomous agent, and fidelity to what the owner wants to exist. Draft 3 of `plan.md` applies their findings:

- **Fidelity:** the fork tree is back in P5; the first instance of an OS user keeps the user's own Claude config folder; one conversation list for each instance (D13); project search and filters; Claude Code's background tasks shown from P5; approvals only for actions that reach other people; the install path before P8; a per-phase lesson check; concrete tools and numbers in §13; P8 as the end of the autonomous run.
- **Implementability:** the exact pskill interface (§5.4); `hook_files: []` in the vault; setting sources, plugins and permissions for each mode (§5.1); one core process with a local API (§4.3); the home layout, port and roles (§4.4); the session record (§4.5) and the event union (§4.6); exit codes; sync defaults and conflict handling (§6); project trust (§12); fakes and `owner-todo.md`; checkable "done when" criteria; agent commit rights.
- **Decisions ledger:** lesson 28 now says "no ruleset for now"; `implement` is delegation to a project's own skills (§5.3); the confirmed project list moves into the vault in P1; append is the Assistant prompt default until spike S4 decides; the idle sweep runs every 60 seconds, close to "commit on every change"; the open questions have defaults (§16).
